### 2. 내 말로 설명하기

운영체제는 응용 프로그램들을 관리하는 가장 큰 프로그램이다. 
운영체제가 없으면 하드웨어 환경에서 프로그램을 만들어야 된다.
운영체제는 커널 모드, 사용자 모드 두 가지 모드가 존재한다. 따라서 이중 모드를 가지고 있다.
커널 모드에서는 운영체제 실행 권한을 가진다. 사용자 모드에서 커널 모드로 바꾸기 위해서는 시스템 함수를 사용한다.
운영체제는 프로세스 관리, 파일 시스템 관리, 자원 접근 및 할당 일들을 한다.

### 3. 헷갈려서 AI에게 확인한 부분
- 처음 헷갈렸던 내용: 운영체제에서 사용자 모드는 어떤 경우 사용되는가?
- AI에게 물어본 질문:운영체제에서 사용자 모드에는 왜 필요하고, 어떤 일들을 처리해?
- AI 답변을 보고 이해한 내용: 커널 영역은 모든 메모리에 접근 가능하기 때문에, 버그 발생 시 시스템 전체가 망가질 위험이 있다. 이를 막기 위해 일반 프로그램은 제한된 사용자 영역에서 실행시켜 안전하게 보호한다. 실행 흐름 실제 연산과 로직은 사용자 영역에서 처리하고, 파일 읽기/네트워크 등 하드웨어가 필요한 작업은 System Call로 커널에 요청한다. 커널이 처리한 뒤 결과를 사용자 영역으로 돌려준다.


### 4. 개발 또는 일상과 연결해 본 예시
운영체제 마다 정의한 시스템 함수가 달라서, 작성했다가 오류가 난 적이 있다. 

### 5. 추가로 알아보고 싶은 내용

운영체제에서 커널이라는 개념은 언제 생겼고, 처음부터 메모리 접근 및  실행 권한은 커널 영역에만 권한이 있었는지에 대해 알고 싶다.

## CH 11장 프로세스와 스레드 

### 1. 핵심 개념 3개
- 문맥 교환
-  PCB 
- Fork- exec
   
### 2. 내 말로 설명하기

프로세스는 cpu에 모든 자원이 할당될 수 없기에 순서대로 cpu에 넣어주는 하나의 데이터 덩이리이다.
PCB 는 옷 가격표라고 생각하면 된다. 여기에는 프로세스 번호, 레지스터 값 등 해당 프로세스의 중요한 정보가 저장된다.
레지스터 값은 PCB에 저장되고, cpu에 다시 프로세스를 실행할 때 어디까지 진행됐는지를 확인하기 위한 값이다.
문맥 교환에서 문맥은 해당 프로세스가 다시 cpu의 할당을 받을 때 저장된 중간 정보를 백업하는 것이다. 
프로세스는 생성 -> 준비 -> 실행 -> 대기 -> 종료 5단계이다.
부모 프로세스는 fork 호출로 자신을 복제한 자식 프로세스를 생성한다. 자식 프로세스는 exec 함수를 통해 자신만의 프로세스를 작성한다. 
하나의 프로세스에는 여러 개의 스레드를 가질 수 있다. 
모든 스레드들은 프로세스의 자원은 공유한다. 
프로세스는 자원을 공유하지 않는다. 스레드는 자원을 공유한다. 

### 3. 헷갈려서 AI에게 확인한 부분
- 처음 헷갈렸던 내용:  PCB가 일이 끝나면 폐기된다고 하는데 그러면 프로세스가 완전히 끝난 시점에서 파기되는지, 필요한 경우 복구는 되는지?
- AI에게 물어본 질문: PCB는 언제 폐기되는가, 북구도 가능한가?
- AI 답변을 보고 이해한 내용: PCB는 부모 프로세스가 자식 프로세스로부터 종료 선언을 받은 wait 함수 가 선언된 이후에 폐기하고, 다시 복구는 불가능하다. 
- 아직 남은 질문:  문맥 교환에서 말하는 문맥은 각 운영체제마다 하나만 존재하는지. 

### 4. 개발 또는 일상과 연결해 본 예시
버퍼 오버플로우는 결국, 프로세스가 다음에 실행할 주소를 저장해 둔 레지스터 값을 스택 overflow를 통해 덮어써서, 해커가 원하는 코드로 실행 흐름을 바꿀 수 있음을 말하는 것이다.

### 5. 추가로 알아보고 싶은 내용

하나의 응용 프로그램은 하나의 프로세스를 가질까? 아니면 여러개의 프로세스를 가지는지가 궁금하다.

## CH 12장 CPU 스케줄링 

### 1. 핵심 개념 3개

- 프로세스의 우선순위 
- 스케줄링 큐 
- CPU 스케줄링 알고리즘 

   
### 2. 내 말로 설명하기
입출력 작업이 맞춘 프로세스는 대기 상태에 머무르는 시간이 많기 때문에  cpu 점유율이 높은 프로세스보다 프로세스 우선순위가 높다.
PCB 에는 프로세스 우선순위 정보가 저장된다. 
스케줄링 큐는 FIFO 원칙이 있는 큐와 다르게 여러 개의 큐를 두고 그 안에 프로세스를 적재하고, 필요한 프로세스부터 꺼내서 쓴다. 
선점형 스케줄링은 얼마든지 다른 프로세스가 cpu에서 동작하는 것을 중지하고, 자기가 cpu에서 동작할 수 있다. 
비선점형 스케줄링은 아무리 급한 프로세스가 있어도  정해진 프로세스가 타임 인터럽트 가 발생하기 전까지 계속 사용할 수 있는 것이다. 
CPU 스케줄링 방식은 선입선출 방식, SJF [처리 시간 짧은 프로세스] 방식, 라운드 로빈 [ CPU에서 사용할 수 있는 시간 할당] 방식 ,SRT [남은 작업 시간이 짧은 프로세스] 방식, 우선단위 스케줄링
우선순위 스케줄링은 기아 현상 문제가 있다. 우선순위가 낮은 프로세스가 계속해서 순서가 뒤로 밀리는 현상 -> 이를 해결하는 방식 [ 에이징 기법] 
다단계 큐 스케줄링도 기아 현상이 발생할 수 있다. -> 다단계 피드백 큐 스케줄링 큐 간의 이동이 가능한 형태. 

### 3. 헷갈려서 AI에게 확인한 부분
- 처음 헷갈렸던 내용: 스케줄링 큐는 뭐를 기준으로 큐를 만들고, 같은 프로세스를 가진 큐는 없는지 
- AI에게 물어본 질문: 스케줄링 큐는 어떠한 기준으로 만들어지고, 큐 내에 겹치는 프로세스는 없어? 
- AI 답변을 보고 이해한 내용: 스케줄링 큐는 프로세스의 현재 상태를 기준으로 나뉘고, 하나의 프로세스는 동시에 하나의 큐에만 존재하며 상태가 바뀔 때마다 큐를 이동한다. 
다단계 큐와 같이 용도에 나눠서 큐를 분리하는 방식도 있다. 

### 4. 개발 또는 일상과 연결해 본 예시
여러 가지 일을 할 때 우선순위가 높은 일부터 처리하긴 하지만, 제본 같이 내가 맡기고 나중에 서점에 찾으러 가는 일을 우선순위를 높여서 먼저 처리하고 그다음에 할 일을 차근차근한다.

### 5. 추가로 알아보고 싶은 내용
강의에는 안 나온 스케줄링 방식에는 또 뭐가 있는지 궁금하다.
문맥 교환 오버헤드가 뭔지, 문맥 교환에서의 문맥은 운영체제마다 하나만 있는지 궁금하다.

## CH 13장  프로세스 동기화 

### 1. 핵심 개념 3개

- 상호 배제 
- wait , signal 
- 임계 구역 
   
### 2. 내 말로 설명하기
프로세스 동기화가 중요한 이유는 프로세스에서 순서가 중요한 경우나, 다른 B 프로세스가 A 프로세스의 실행된 뒤에 실행되어야 하는 경우가 있을 수 있다.
바쁜 대기 방식은 계속 프로세스가 잠겨있는지를 확인하는 방식임으로 그다지 좋은 방식이 아니다. 
세마포어  방식은 임계 구역에 들어갈 수 있는지를 계속 확인하다가, 들어가는 것. wait과 signal의 방식을 앞뒤로 둬서 프로세스의 할당을 조절한다. 
wait() 은 프로세스가 임계 구역을 빠져나오기를 기다리는 것이고, signal 함수는 잠시 일시정지 하고 다른 프로세스가 일을 다 끝난 다음 재게 하는 방식도 있고, 아예 프로세스를 꺼내고 실행이 완료된 뒤에 다시 넣는 방식도 있다.
모니터에는 하나의 프로세스만 존재해야 한다. 


### 3. 헷갈려서 AI에게 확인한 부분
- 처음 헷갈렸던 내용: 뮤텍스 락이 프로세스가 실행되는 것을 잠가야 되지 왜 임계 구역을 잠그고 열어야 되는지가 궁금하다. 
- AI에게 물어본 질문: 뮤텍스 락이 임계구역에 왜 잠금 기능을 넣어야 되는지? 
- AI 답변을 보고 이해한 내용: 임계 구역은 프로세스가 대기하는 공간이 아니라, 공유 데이터의 순서를 보장하기 위한 구역이다. 공유 데이터의 충돌을 방지하기 위해서 쓰인다.
